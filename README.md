> [!NOTE]
> BETCHU는 현재 **MVP 개발 환경 구축과 기능 구현 시작 단계**입니다. `frontend`에는 Expo 모바일 앱, `backend`에는 Spring Boot API scaffold가 있으며 실제 서비스 기능은 아직 구현 전입니다. 이 README는 현재 확정된 MVP 규칙을 요약하고 [서비스 기획안 v0.1](./docs/betchu기획안.md)의 세부 계약을 기준으로 구현합니다.

## 서비스 소개

BETCHU(배츄)는 커플의 일상적인 약속을 퀘스트로 바꾸고, 약속을 지킨 결과를 몬스터의 성장으로 남기는 모바일 게임입니다.

기록 중심의 커플 앱과 개인 중심의 습관 관리 앱 사이에서, 두 사람이 함께 약속하고 확인하며 성장하는 경험을 지향합니다. 실제 생활에서의 행동은 츄코인, 경험치, 아이템과 전투력으로 이어지고, 시간이 쌓일수록 둘만의 플레이 기록이 됩니다.

| 항목 | 내용 |
| --- | --- |
| 장르 | 커플 약속 게임 · 몬스터 육성 · 아이템 수집 |
| 이용 인원 | 연결된 커플 2명 |
| 목표 플랫폼 | iOS · Android 모바일 앱 |
| 핵심 타깃 | 만 14세 이상, 게임을 가볍게 즐기는 10대 후반~20대 커플 |
| 핵심 방향 | 경쟁 50% + 협동 50% |
| 실제 현금 | 코인 구매·환전·사용자 간 송금 없음 |
| AI API | 사용하지 않음 |

## BETCHU가 만드는 경험

- **약속을 퀘스트로**: 취침, 운동, 공부, 연락, 집안일 같은 일상의 약속을 구체적인 성공 조건과 함께 등록합니다.
- **서로의 동의로 시작**: 파트너가 난이도와 조건을 확인하고 성공 또는 실패를 예상한 뒤 승인·수정 요청·거절할 수 있습니다.
- **파트너의 최종 확인으로 정산**: 수행 기간이 끝나면 파트너가 실제 결과를 성공 또는 실패로 판정하고 최종 승인합니다.
- **행동을 성장으로**: 성공한 퀘스트는 츄코인·계정 경험치와 배츄의 영구 성장 기록으로 이어집니다.
- **경쟁과 협동의 균형**: 평일에는 전투력·연승·주간 성장량을 비교하고, 주말에는 두 배츄의 합산 전투력으로 간이 협동 보스에 도전합니다.
- **둘만의 기록**: 완료한 퀘스트와 성장 과정이 장기적으로 커플의 공동 플레이 기록이 됩니다.

## 핵심 게임 루프

```text
커플 연결
  ↓
스타팅 배츄 · 이름 선택
  ↓
퀘스트 생성 · 난이도와 츄코인 설정
  ↓
파트너의 성공·실패 예상 선택과 시작 승인
  ↓
퀘스트 수행 · 파트너 예상 표시
  ↓
파트너의 실제 결과 입력과 최종 승인
  ↓
성공·실패 정산 또는 무효 처리
  ↓
뽑기 · 아이템 장착
  ↓
배츄 성장 · 전투력 상승
  ↓
파트너 성장 비교 · MVP 간이 협동 보스
  ↓
다음 퀘스트
```

정적 외형 진화와 간이 협동 보스까지 MVP에 포함합니다. `P2-4` 커플 PvP·정식 레이드·월간 시즌·고급 진화 애니메이션은 이 루프를 확장하는 후속 콘텐츠입니다.

## 핵심 시스템

### 1. 커플 연결과 온보딩

만 14세 이상 확인과 필수 정책 동의 후 간편 로그인으로 가입합니다. 초대 코드는 24시간 동안 한 번만 사용할 수 있으며, 상대방이 코드를 입력한 뒤 두 사람이 서로의 프로필을 확인하고 모두 동의해야 연결됩니다. 연결 종료·차단은 상대방 동의 없이 즉시 관계 접근을 차단합니다.

각 사용자는 이름과 함께 능력치가 동일한 스타팅 배츄 하나를 선택하고, 가입 활성화 시 계정당 한 번 1,000C를 받습니다.

| 스타팅 배츄 | 색상·외형 방향 | 서버 코드 |
| --- | --- | --- |
| 별빛 | 노랑·보라, 밤하늘과 별빛 | `STARLIGHT` |
| 파도 | 하양·파랑, 말랑한 파도와 바다 | `WAVE` |
| 노을 | 빨강·갈색, 따뜻한 노을과 땅 | `SUNSET` |
| 숲 | 초록·갈색, 포근한 나무와 숲 | `FOREST` |

스타팅 배츄는 공통 알 모습으로 시작하고, 부화한 뒤 선택한 종의 색상과 외형이 나타납니다.

### 2. 퀘스트와 파트너 시작 승인

퀘스트에는 제목, 카테고리, 성공 조건, 난이도, 걸 코인, 수행 마감과 결과 확인 시간을 설정합니다. MVP에서는 한 사람이 수행하고 상대방이 확인하는 **개인 퀘스트**를 먼저 구현합니다.

```text
DRAFT ── submit v1 ──→ PENDING_APPROVAL
DRAFT ── discard ──→ DISCARDED
PENDING_APPROVAL ── recall ──→ DRAFT
PENDING_APPROVAL ── request change ──→ CHANGE_REQUESTED ── submit v2 ──→ PENDING_APPROVAL
PENDING_APPROVAL ── predict & approve ──→ ACTIVE ──→ AWAITING_RESULT
PENDING_APPROVAL ── reject / deadline ──→ REJECTED | APPROVAL_EXPIRED
ACTIVE ── mutual cancel before due ──→ CANCELED
AWAITING_RESULT ── partner selects result ──→ PENDING_FINAL_APPROVAL
PENDING_FINAL_APPROVAL ── final approve ──→ SUCCESS | FAILURE
AWAITING_RESULT ── reject / deadline ──→ INVALID
PENDING_FINAL_APPROVAL ── reject / deadline ──→ INVALID
```

핵심 규칙은 **파트너가 시작 승인하기 전까지만 수정 가능**입니다.

- `DRAFT`: 작성자만 볼 수 있으며 자유롭게 수정·폐기합니다.
- `PENDING_APPROVAL`: 직접 덮어쓰지 않고 먼저 회수한 뒤 수정합니다.
- `CHANGE_REQUESTED`: 요청받은 내용을 고쳐 `v1 → v2`처럼 새 불변 버전으로 다시 보내며 이전 승인은 무효화합니다.
- `ACTIVE`: 승인된 버전과 파트너가 선택한 성공·실패 예상을 고정해 두 사람에게 수행 기간 동안 보여줍니다. 이후 조건을 바꾸려면 수행 마감 전에 양쪽 합의로 취소하고 새 퀘스트를 만듭니다.
- 시작 승인 마감은 `수행 마감 - 최소 수행 시간`으로 서버가 계산하며, 마감되면 코인을 잠그지 않고 `APPROVAL_EXPIRED`로 종료합니다.

파트너에게는 해당 퀘스트의 제목·성공 조건·난이도·건 코인·예상 보너스·시간·인증 방식·버전·수정 항목을 보여줍니다. 파트너는 퀘스트를 승인할 때 도전자의 성공 또는 실패를 예상해 하나를 선택하며, 이 선택은 퀘스트 수행 기간 동안 두 사람의 화면에 표시됩니다. 작성자의 전체 잔액·지갑 내역·뽑기 및 구매 내역·미제출 초안은 공개하지 않습니다.

### 3. 파트너 결과 판정과 최종 승인

수행 기간이 끝나면 파트너가 성공 조건과 필요한 인증 자료를 확인하고 실제 결과를 `SUCCESS` 또는 `FAILURE`로 입력합니다. 입력한 결과는 최종 승인 전까지 정산에 반영되지 않으며, 파트너가 최종 승인한 뒤 서버 정산이 완료되어야 결과가 확정됩니다.

- 파트너가 성공을 입력하고 최종 승인하면 `SUCCESS`로 정산해 잠긴 원금과 성공 보너스를 지급하고 XP와 인정 성공 수를 반영합니다.
- 파트너가 실패를 입력하고 최종 승인하면 `FAILURE`로 정산해 잠긴 코인을 소각하고 성공 보너스와 XP를 지급하지 않습니다.
- 파트너가 결과를 인정할 수 없어 최종 승인을 거절하거나 결과 확인 기한까지 최종 승인하지 않으면 `INVALID`로 종료합니다.
- `INVALID`는 성공이나 실패로 정산하지 않습니다. 잠긴 원금만 반환하고 성공 보너스·XP·인정 성공 수·연승·케미 게이지에는 반영하지 않습니다.
- 사용자당 한 번인 튜토리얼은 `FAILURE` 또는 `INVALID`여도 잠긴 원금만 반환합니다.

두 사람이 결과를 따로 입력하거나 서로의 결과를 비교하는 절차는 없습니다. 결과 불일치에 따른 분쟁 상태와 24시간 재응답 절차도 사용하지 않습니다.

### 4. 츄코인 경제

츄코인은 서비스 안에서만 사용하는 가상 재화입니다. 퀘스트에 코인을 걸고 파트너가 성공으로 최종 승인하면 원금과 시작 승인 시 확정된 성공 보너스를 받습니다. 파트너가 실패로 최종 승인하면 걸었던 코인을 잃고, 최종 승인을 받지 못해 무효가 되면 원금만 반환받습니다. 0C 퀘스트도 만들 수 있습니다.

| 난이도 | MVP 선택 가능 금액 |
| --- | --- |
| ★·★★ | 0C / 100C |
| ★★★ | 0C / 100C / 200C |
| ★★★★ | 0C / 100C / 200C / 300C |
| 자유 입력 | 표시 난이도와 관계없이 최대 100C |

★★★★★ 500C는 별도 경제 검증이 필요한 후속 장기 퀘스트 제안입니다. MVP에서는 코인을 건 퀘스트를 사용자당 하루 2개로 제한하고, 성공 보너스를 하루 300C, 저난도 보너스를 그중 100C로 제한합니다. 잔액이 100C 미만이고 잠긴 코인이 없으면 100C를 받을 수 있는 P0 구조 퀘스트를 제공하되, 7일에 한 번·최근 30일 최대 2회로 제한합니다.

현금 구매·환전·사용자 간 송금은 제공하지 않습니다.

### 5. 배츄 성장과 아이템

성장은 계정 능력치와 배츄 외형을 분리해 관리합니다.

- **XP·계정 레벨**: 퀘스트 난이도와 연승 보너스로 오르며 기본 HP·ATK·전투력을 높입니다.
- **배츄 인정 성공 수**: 일반 개인 퀘스트가 서버에서 최종 `SUCCESS`로 정산될 때 활성 배츄에 1회 기록되며 외형 성장과 마일스톤을 결정합니다.
- **장비**: 무기·방어구·장신구의 HP·ATK가 최종 전투력에 추가됩니다.

| 인정 성공 기준 | 성장·보상 |
| --- | --- |
| 튜토리얼 성공 또는 활성 알의 첫 인정 성공 | `EGG → BABY` 부화 |
| 20회 | `BABY → INTERMEDIATE` 중간 성장 |
| 40회 | `INTERMEDIATE → FINAL` 최종 진화 |
| 60회 | 종별 오라·칭호·전투력 0 숙련 장신구 |
| 80회 | MVP에서 달성 기록, P2에서 미보유 배츄 알 선택권 생성 |

성장은 결과 버튼을 누른 순간이 아니라 **파트너의 최종 승인을 받고 서버의 최종 정산 트랜잭션이 커밋된 순간** 반영됩니다. 튜토리얼 성공은 부화만 처리하고 인정 성공 수는 0으로 유지합니다.

츄코인은 일반 100C·고급 500C·전설 1,000C 뽑기에 사용합니다. 확률과 천장 진행도를 공개하고, 획득한 무기·방어구·장신구를 장착해 전투력을 높입니다. MVP의 중복 아이템은 자동으로 조각으로 변환합니다. P2부터 새 중복 아이템은 24시간 안에 `교환용으로 보관` 또는 `조각으로 변환`을 선택하며, 미선택 시 자동으로 조각이 됩니다.

### 6. MVP 경쟁·협동

홈에서 두 사람의 전투력·연승·이번 주 성장량을 나란히 비교합니다. 유효한 일반 개인 퀘스트를 파트너의 최종 승인으로 `SUCCESS` 또는 `FAILURE`로 정산할 때 케미 게이지가 1칸 오르고, 주간 10칸을 채우면 간이 협동 보스가 열립니다. `INVALID` 퀘스트는 케미 게이지에 반영하지 않습니다.

홈의 퀘스트 현황에는 **승인 대기·진행 중·결과 대기**를 각각 몇 건인지 함께 표시합니다. `승인 대기`는 `PENDING_APPROVAL`, `진행 중`은 `ACTIVE`, `결과 대기`는 `AWAITING_RESULT`와 `PENDING_FINAL_APPROVAL` 상태의 퀘스트를 집계합니다.

주말에 두 사람이 모두 참여하면 당시 최종 전투력을 합산해 커플당 주 1회 자동 판정합니다. 요구 전투력 이상이면 두 사람 모두 일반 뽑기권 1장을 받고, 실패·미참여·관계 종료에는 보상도 손실도 없습니다.

| 뽑기와 장비 | 일반·고급·전설 뽑기, 확률·천장, 인벤토리, 중복 조각, 장비 3종 장착 |
| 경쟁과 협동 | 파트너 성장 비교 카드, 케미 게이지, 자동 판정 간이 협동 보스 |
| 운영 품질 | 거래성 푸시·인앱 대기함, 인증 자료 보호·삭제, 접근성 |

### P1 · MVP 직후 개선

- 퀘스트 기록
- 일일 출석
- 이벤트·홍보 알림
- 아이템 도감

### MVP에서 제외하는 기능

- 커플 PvP 실제 전투(`P2-4`)와 공격·방어·스킬 선택형 정식 레이드
- 아이템 강화와 고급 진화 애니메이션
- 월간 시즌과 커플 프로필 공유
- 복수 배츄 보관함·80회 알 선택·활성 배츄 교체
- 중복 아이템 1:1 교환과 꾸미기·보유 아이템 선물
- 커플 방 꾸미기와 유료 결제

정적 4단계 성장과 간이 협동 보스는 제외 항목이 아니라 MVP P0입니다.

## 후속 P2 확장

| 단계 | 확정 방향 |
| --- | --- |
| P2-1 | 상점에서 상대에게 사 주는 전투력 0 귀속 꾸미기 선물 |
| P2-2 | 현재 커플끼리 중복 아이템 1:1 교환 |
| P2-3 | 기존 보유 꾸미기·저등급 중복 아이템 선물 |
| P2-4 | 현재 연결된 커플끼리 배츄로 대결하는 선택형 3턴 PvP |

- **80회 새 배츄**: 퀘스트 성공 80회를 달성하면 아직 보유하지 않은 배츄 중 하나를 선택해 받을 수 있습니다. 새 배츄는 알부터 성장하지만 계정 레벨·장비·코인은 유지됩니다.
- **아이템 교환**: 커플 연결 7일 후부터 서로의 중복 아이템을 교환할 수 있습니다. 자신이 사용할 1개는 남겨야 하며, 주 3회까지 교환할 수 있습니다.
- **아이템 선물**: 상점에서 꾸미기 아이템을 구매해 파트너에게 선물할 수 있습니다. 이후에는 보유한 일부 중복 아이템도 선물할 수 있도록 확장합니다.
- **커플 PvP**: 한 사람이 대전을 신청하고 상대가 수락하면 각자의 활성 배츄와 장비 능력치를 고정해 3턴 동안 `공격·방어·스킬` 중 하나를 동시에 선택합니다. 공개 매칭이나 다른 커플과의 대전은 제공하지 않습니다. PvP는 퀘스트 성공 수·XP·연승·케미 게이지에 영향을 주지 않으며, 코인 대신 능력치 없는 배틀 메달 꾸미기 보상을 사용합니다.
- **정식 레이드 순환**: 잠꾸러기 마왕 → 미루기 슬라임 → 산만이 도깨비 → 시즌 한정 보스를 4주 단위로 순환합니다. 보스 구성은 확정이며 선택형 전투와 보상 수치는 후속 검증 대상입니다.

## 개발 로드맵

1. **기본 연결** — 로그인, 연령·정책 동의, 안전한 커플 초대·연결·종료, 스타팅 배츄, 홈
2. **퀘스트와 코인** — 초안·불변 버전·승인 마감, 파트너 예상 표시, 최종 결과 승인, 무효 처리, 난이도별 베팅, 지갑 원장, 구조 퀘스트, 거래성 알림
3. **몬스터 성장** — XP·레벨·연승·능력치, 부화와 인정 성공 20·40·60·80 마일스톤, 정적 외형
4. **뽑기와 장비** — 세 종류의 뽑기, 확률 버전·천장, 인벤토리, 중복 조각, 장비 장착
5. **MVP 경쟁·협동 검증** — 파트너 비교, 케미 게이지, 양쪽 참여 간이 협동 보스
6. **출시 품질** — 접근성, 개인정보 수명주기, 관계 종료, 경제·원자성·중복 정산 검증과 P1 개선
7. **서비스 확장** — `P2-4` 커플 PvP, 4주 순환 정식 레이드, 복수 배츄, 80회 알 선택, 교환·선물, 시즌·꾸미기·공유 카드

## 제품 원칙

### 건강한 관계를 위한 설계

- 일반 개인 퀘스트는 파트너가 거절하거나 수정을 요청할 수 있어야 합니다.
- 연결 종료·차단은 상대 동의 없이 즉시 실행하며 상대 프로필·공동 화면·인증 자료 접근을 바로 막습니다.
- 인증 자료는 선택 사항이며 비공개로 저장하고, 현재 연결된 커플에게만 권한을 부여하며 보관·삭제 기한을 관리합니다.
- 외모 평가, 식사 강요, 위치 인증, 사생활 공개, 위험한 행동과 관계 통제를 유도하는 기본 퀘스트는 제공하지 않습니다.
- 실패 문구는 사용자를 비난하지 않고 다음 도전을 돕는 방향으로 작성합니다.
- 경쟁으로 한 사람만 계속 뒤처지지 않도록 협동 콘텐츠와 보정 장치를 함께 설계합니다.
- 스크린리더·글자 확대·충분한 명암비·모션 감소를 MVP 출시 기준에 포함합니다.

### 초기 버전의 서비스 경계

초기 버전에서는 다음 기능을 제공하지 않습니다.

- 실제 돈을 이용한 코인 구매·환전과 확률형 유료 상품을 제공하지 않습니다.
- 위치, 메신저, 휴대폰 사용 시간을 자동으로 감시하지 않습니다.
- AI API를 사용하거나 AI로 약속의 성공 여부를 판정하지 않습니다.
- 다른 커플과의 공개 경쟁을 제공하지 않습니다.
- MVP에서는 사용자 간 아이템 거래를 제공하지 않으며, P2에서 현재 연결된 커플만 제한적으로 교환·선물할 수 있습니다.

### 백엔드 정합성

- 모든 코인 변화를 거래 원장에 기록하고 사용 가능 잔액과 잠긴 잔액을 분리합니다.
- 승인·취소·결과·무효·정산은 서버 트랜잭션과 멱등 키로 한 번만 처리해 중복 지급·소각·환불을 방지합니다.
- 퀘스트 제출본은 불변 버전으로 보존하고 승인된 버전만 수행·정산 기준으로 사용합니다.
- 시작 승인 시점에 잔액·난이도별 한도·일일 슬롯·보너스 예산을 함께 검증하고 예약합니다.
- 뽑기 결과와 천장은 서버에서 결정하며 사용한 확률 버전과 결과를 함께 기록합니다.
- 성장 단계·인정 성공 수·보상은 코인 및 XP 정산과 같은 트랜잭션에서 반영합니다.

## 개발 환경 빠른 시작

요구 환경은 Node.js 24 LTS, pnpm 10, Java 21, Docker Desktop입니다. 전체 기준은 [개발 환경 정의](./development-environment.yaml)를 참고합니다.

```bash
# 1. PostgreSQL, MinIO, ClamAV
docker compose -f infra/compose.yaml up -d

# 2. 백엔드
cd backend
./gradlew bootRun

# 3. 새 터미널에서 프론트엔드
cd frontend
cp .env.example .env.local
pnpm install --frozen-lockfile
pnpm start
```

Windows에서는 백엔드 실행에 `gradlew.bat bootRun`을 사용합니다. Android Emulator에서 API에 연결할 때는 `frontend/.env.local`의 주소를 `http://10.0.2.2:8080/api/v1`로 변경합니다.
