# BETCHU 디자인 의뢰서

> 문서 목적: BETCHU의 MVP 디자인 범위와 후속 P2 디자인 범위를 분리하고, 디자이너가 견적·일정·산출물을 명확히 제안할 수 있도록 필요한 화면, 캐릭터, 아이템, 컴포넌트와 납품 기준을 정리한다.
>
> 현재 상태: 서비스 기획 및 MVP 정의 완료, 개발 착수 전

1. [README](../README.md) — 현재 확정된 제품 방향과 MVP 범위
2. [서비스 기획안](./betchu기획안.md) — 상태, 정책, 화면별 세부 규칙

## 2. 서비스 요약

BETCHU는 커플이 일상의 약속을 퀘스트로 만들고, 츄코인을 걸어 수행한 뒤 파트너의 확인을 받아 배츄를 성장시키는 2인용 모바일 게임이다.

- 플랫폼: iOS·Android 모바일 앱
- 이용 인원: 현재 연결된 커플 2명
- 대상: 만 14세 이상, 10대 후반~20대 커플
- 핵심 경험: 약속 생성 → 파트너 승인 → 수행 → 결과 확인 → 정산 → 성장·수집
- 핵심 감정: 귀여움, 응원, 함께 성장하는 성취감, 가벼운 경쟁과 협동
- 실제 현금: 사용하지 않음
- 공개 경쟁: 제공하지 않음
- AI 기능: 사용하지 않음

## 3. 디자인 목표

### 3.1 반드시 전달해야 하는 인상

- 커플 기록 앱보다 게임답고, 도박 앱보다 건강하고 귀여워야 한다.
- 배츄는 사용자를 심판하는 캐릭터가 아니라 실패해도 다시 도전하도록 응원하는 동반자여야 한다.
- 두 사람의 경쟁은 가볍게 표현하고, 상대를 비난하거나 열등감을 만드는 연출은 피한다.
- 퀘스트 승인·결과 확인·코인 정산처럼 중요한 정보는 귀여운 연출보다 이해하기 쉬운 정보 구조를 우선한다.
- 성별 고정 관념에 기대지 않는 중립적인 색상·캐릭터·카피를 사용한다.

### 3.2 피해야 하는 방향

- 카지노 슬롯, 현금 칩, 사행성 게임처럼 보이는 연출
- 성공과 실패를 색상만으로 구분하는 방식
- 과도하게 유아용으로 보이는 UI
- 커플의 연락, 위치, 외모나 사생활을 통제하는 이미지와 문구
- 실패한 사용자를 조롱하거나 파트너에게 책임을 돌리는 연출
- 인증 사진이나 퀘스트 내용을 잠금 화면에서 노출하는 디자인

## 4. 전체 의뢰 범위

디자인 범위는 다음 네 묶음으로 나눈다.

| 구분 | 작업 내용 | 우선순위 |
| --- | --- | --- |
| 브랜드·비주얼 기반 | 로고, 앱 아이콘, 색상, 타이포그래피, 아이콘, 일러스트 원칙 | MVP 필수 |
| UX·UI 디자인 시스템 | 토큰, 컴포넌트, 상태, 접근성 규격 | MVP 필수 |
| MVP 화면·프로토타입 | 20개 화면군과 핵심 상태·예외 흐름 | MVP 필수 |
| 캐릭터·아이템 아트 | 배츄 13개 기본 이미지, 아이템 28개, 오라·보스 등 | MVP 필수 |
| P2 확장 화면·아트 | 교환, 선물, 꾸미기, 새 알, 정식 레이드, 커플 PvP | 별도 견적 |

P2는 MVP 납품을 지연시키지 않도록 별도 페이지·마일스톤·견적으로 구분한다.

## 5. 브랜드와 비주얼 기반 디자인

### 5.1 필요한 산출물

- BETCHU 한글·영문 워드마크
- 심볼 로고
- 앱 아이콘
- 스플래시 화면용 로고 조합
- 밝은 배경·어두운 배경·단색 버전
- 최소 사용 크기와 여백 규칙
- 주조색·보조색·상태색·배경색·테두리색 팔레트
- 한글·영문·숫자 타이포그래피 체계
- 선형·채움형 아이콘 스타일 가이드
- 배츄 일러스트의 형태, 눈·입, 선 굵기, 명암과 그림자 규칙

### 5.2 스타팅 배츄 팔레트 방향

아래 네 종류는 능력치가 같고 외형과 색상만 다르다.

| 배츄 | 필수 색상 방향 | 이미지 키워드 |
| --- | --- | --- |
| 별빛 | 노랑·보라 | 밤하늘, 별빛, 반짝임 |
| 파도 | 하양·파랑 | 바다, 말랑한 파도, 물결 |
| 노을 | 빨강·갈색 | 따뜻한 노을, 땅, 포근함 |
| 숲 | 초록·갈색 | 나무, 잎, 숲, 안정감 |

색상 수치는 아직 확정되지 않았다. 디자이너가 접근성 명암비를 만족하는 실제 팔레트를 제안해야 한다.

## 6. MVP UX·UI 화면 디자인

### 6.1 공통 하단 내비게이션

다섯 개의 주요 영역을 한 손으로 이동할 수 있게 구성한다.

```text
[홈] [퀘스트] [배츄] [상점 또는 뽑기] [배틀]
```

`몬스터/배츄`, `상점/뽑기` 명칭은 기획안과 현재 와이어프레임이 다르므로 최종 디자인 전 기획자가 확정해야 한다. 디자이너는 확정 전까지 컴포넌트가 어느 명칭에도 대응할 수 있도록 너비를 설계한다.

### 6.2 MVP 화면군

아래 20개 화면군을 디자인한다. 한 화면군에 여러 단계나 상태가 있으면 각각 별도 프레임으로 만든다.

| 번호 | 화면군 | 반드시 포함할 화면·상태 |

| 1 | 스플래시 | 로고, 서비스 문구, 로딩 |
| 2 | 로그인·가입 | 소셜 로그인, 만 14세 이상 확인, 필수·선택 동의, 가입 불가 |
| 3 | 커플 연결 | 코드 생성, 코드 입력, 상대 미리보기, 양쪽 최종 확인, 대기, 철회, 거절, 만료, 연결 완료 |
| 4 | 스타팅 배츄 선택 | 4종 비교, 선택 상태, 배츄 이름 입력, 확인 |

기획안에서는 설정을 포함해 20개 화면군으로 묶었지만, 실제 제작 목록에서는 퀘스트 수정·진행 중 화면을 별도 화면군으로 나누고 인벤토리·장비를 한 화면군으로 묶어 총 21개로 관리한다.

### 6.3 홈 화면 필수 정보 구조

홈은 다음 순서를 유지한다.

1. 내 배츄 상태와 현재 츄코인
2. `승인 대기 · 진행 중 · 결과 대기` 건수
3. 바로 처리해야 할 퀘스트
4. 파트너와 전투력·연승·이번 주 성장량 비교
5. 이번 주 케미 게이지와 간이 협동 보스 상태
6. 새 퀘스트 만들기

상태 건수의 의미는 다음과 같다.

| 화면 문구 | 상태 |
| --- | --- |
| 승인 대기 | `PENDING_APPROVAL` |
| 진행 중 | `ACTIVE` |
| 결과 대기 | `AWAITING_RESULT`, `PENDING_FINAL_APPROVAL` |

세 상태는 색상 외에도 아이콘·문구·숫자로 구분한다.

## 7. 반드시 연결해야 하는 핵심 프로토타입

아래 흐름은 정적인 화면 모음이 아니라 클릭 가능한 프로토타입으로 납품한다.

### Flow A. 가입과 커플 연결

```text
스플래시 → 로그인 → 연령·동의 → 초대 코드 생성/입력
→ 상대 미리보기 → 양쪽 최종 확인 → 스타팅 배츄·이름 선택
→ 튜토리얼 → 홈
```

### Flow B. 퀘스트 생성과 시작 승인

```text
홈 → 퀘스트 생성 → 초안 → 파트너에게 전송
→ 파트너의 성공·실패 예상 → 승인
→ 코인 잠금 → 진행 중
```

분기 흐름도 포함한다.

- 작성자의 회수·수정·재전송
- 파트너의 수정 요청
- 파트너의 거절
- 승인 마감 만료
- 승인 시 잔액이나 한도 부족으로 재수정이 필요한 상태

### Flow C. 결과 확인과 정산

```text
결과 대기 → 파트너가 성공 조건·인증 자료 확인
→ 성공 또는 실패 선택 → 최종 확인 → 최종 승인
→ 성공/실패 정산 화면 → 홈·성장 반영
```

판정 거절·기한 만료에 따른 `무효/원금 반환` 흐름도 포함한다.

### Flow D. 성장·뽑기·장비

```text
퀘스트 성공 정산 → XP·인정 성공 수 반영 → 성장 화면
→ 상점 → 확률·천장 확인 → 뽑기 → 신규/중복 결과
→ 인벤토리 → 장비 장착 → 전투력 상승
```

### Flow E. 간이 협동 보스

```text
케미 10칸 달성 → 주말 참여 → 파트너 대기
→ 두 번째 사용자 참여 → 합산 전투력 판정
→ 클리어/실패/만료 → 보상 또는 무보상 종료
```

MVP 간이 보스에는 공격·방어·스킬을 고르는 턴 전투가 없다.

### Flow F. 관계 종료와 안전

```text
설정 → 연결 종료 또는 차단 → 경고·정산 규칙 확인
→ 즉시 상대 접근 차단 → 관계 자원 정리 중
→ 처리 완료와 최종 잔액 확인
```

## 8. 배츄 캐릭터 아트

### 8.1 MVP 최소 수량

| 자산 | 수량 | 설명 |
| --- | ---: | --- |
| 공통 알 | 1 | 모든 종이 공유하는 기본 실루엣 |
| 종 선택 표식 | 4 | 별빛·파도·노을·숲을 구분하는 교체형 오버레이 |
| 아기 배츄 | 4 | 첫 부화 모습 |
| 중간 성장 배츄 | 4 | 인정 성공 20회 |
| 최종 진화 배츄 | 4 | 인정 성공 40회 |
| 종별 숙련 오라 | 4 | 인정 성공 60회, 능력치 없음 |
| 종별 숙련 칭호 배지 | 4 | 인정 성공 60회 |

기획안의 기본 배츄 이미지 수량은 `공통 알 1 + 아기 4 + 중간 4 + 최종 4 = 총 13개`다. 종 선택 표식은 공통 알에 적용하는 별도 오버레이로 제작한다.

### 8.2 필요한 표정·상태

13개 기본 이미지 외에 아래 상태를 최소한의 눈·입·소품 레이어로 재사용할 수 있게 설계한다.

- 기본 대기
- 기쁨·성공
- 아쉬움·실패
- 긴장·마감 임박
- 성장 완료
- 장비 착용
- 보스 참여

고급 진화 애니메이션은 MVP에서 제외한다. MVP에는 성장 전·후 정적 이미지와 모션 감소 사용자를 위한 정적 완료 화면이 필요하다.

## 9. 아이템·게임 아트

```

### 9.3 추가 게임 자산

- 츄코인 아이콘
- 일반·고급·전설 뽑기권 아이콘

- 성공·실패·무효·승인 대기·진행 중·결과 대기 상태 아이콘

Figma에서 개발자가 재사용할 수 있는 컴포넌트와 변형 상태를 만든다.

- 상단 앱 바, 뒤로 가기, 제목, 코인 잔액

- 기본·보조·위험·텍스트 버튼
- 아이콘 버튼과 플로팅 퀘스트 생성 버튼
- 텍스트 입력, 긴 문장 입력, 검색, 날짜·시간 선택
- 체크박스, 라디오, 토글, 세그먼트, 드롭다운
- 퀘스트 카드와 상태 칩
- 배츄 상태 카드와 파트너 비교 카드
- 아이템 카드, 등급 배지, 장비 슬롯
- XP·HP·케미·천장 진행 바
- 코인·XP·능력치 변화 행

- 바텀 시트, 다이얼로그, 토스트, 스낵바

### 10.2 상태 정의

상호작용 컴포넌트에는 가능한 범위에서 다음 상태를 제공한다.

```

퀘스트·선물·대전처럼 서버 처리가 필요한 버튼은 중복 탭을 막는 로딩 상태와 처리 완료 상태를 구분한다.

### 10.3 디자인 토큰

- 색상: 배경, 표면, 텍스트, 테두리, 브랜드, 상태, 희귀도
- 타이포그래피: 제목, 본문, 보조 문구, 숫자, 버튼, 캡션

- 터치 영역과 반응형 여백
- 모션 시간·이징과 모션 감소 대체 규칙

## 11. 중요한 정보·카피 규칙

### 11.1 고정 용어

| 의미 | 화면 용어 |
| --- | --- |
| 서비스 캐릭터 | 배츄 |
| 앱 재화 | 츄코인, 숫자 뒤 `C` |
| 퀘스트에 사용하는 금액 | 걸 코인 또는 `걸기 100C` |
| 파트너가 시작 전에 하는 판단 | 성공 예상 / 실패 예상 |
| 파트너의 실제 판정 | 실제 결과 |
| 정산을 확정하는 행동 | 최종 승인 |
| 외형 성장 기준 | 인정 성공 수 |

`베팅/배팅`, `몬스터/배츄`, `상점/뽑기`를 화면마다 혼용하지 않는다. 최종 용어표는 시안 확정 전에 기획자와 한 번 더 검수한다.

### 11.2 파트너에게 보여야 하는 정보

- 퀘스트 제목과 성공 조건
- 난이도와 건 코인
- 수행·결과 확인 시각
- 인증 방식
- 버전과 수정된 항목

### 11.3 파트너에게 숨겨야 하는 정보

- 상대방의 전체 코인 잔액
- 전체 지갑 거래 내역
- 뽑기·구매 내역
- 전송하지 않은 퀘스트 초안
- 잠금 화면의 퀘스트 제목, 인증 자료, 판정 결과와 금액

## 12. 접근성·안전·개인정보 디자인 기준

아래 항목은 선택 사항이 아니라 MVP 출시 기준이다.

- 일반 텍스트 명암비 4.5:1 이상
- 큰 글자와 주요 UI 명암비 3:1 이상
- iOS 44×44pt, Android 48×48dp 이상의 터치 영역
- 글자 200% 확대에서도 기능과 내용 손실 없음
- 성공·실패·희귀도·기한을 색상만으로 구분하지 않음
- 논리적인 스크린리더 읽기 순서와 포커스 상태 정의
- 뽑기·성장·실패 연출에 건너뛰기 제공
- 모션 감소 설정에서는 정적 이미지로 대체
- 초당 3회 이상 점멸 금지
- 남은 기한은 게이지만이 아니라 텍스트로 표시
- 위험 기능인 연결 종료·차단·신고·탈퇴를 숨기지 않되 실수 실행을 막는 확인 단계 제공
- 인증 이미지는 선택 사항임을 표시하고, 삭제·동의 철회·보관 기간 안내 제공
- 잠금 화면 알림 기본 문구는 개인 내용 없이 `BETCHU에서 확인할 내용이 있어요. 앱을 열어 확인해 주세요.`로 구성

## 13. 후속 P2 별도 디자인 범위

P2는 MVP와 분리해 견적을 요청한다. MVP 디자인 시스템을 그대로 확장할 수 있어야 한다.

| 우선순위 | 화면·기능 | 필요한 핵심 디자인 |
| --- | --- | --- |
| P2 공통 | 배츄 보관함·80회 새 알 | 미보유 알 선택, 복수 배츄, 활성 배츄 교체 |
| P2-1 | 꾸미기 상점·선물 | HEAD·BODY·BACKGROUND 꾸미기, 구매 선물, 수락·거절·72시간 만료 |
| P2-2 | 중복 아이템 교환 | 중복 보관·조각 선택, 양쪽 아이템 선택, 버전 갱신, 양쪽 최종 확인, 24시간 만료 |
| P2-3 | 보유 아이템 선물 | 선물 가능 여부, 귀속, 수락·거절·반환, 재선물 불가 |
| P2-4 | 커플 PvP | 대결 요청·수락, 3턴 공격·방어·스킬 비공개 선택, 턴 결과, 승패, 배틀 메달 |
| P2 | 정식 레이드 | 4주 보스 순환, HP, 두 사람 선택, 합동 효과, 보상 |
| P2 | 월간 시즌 | 통계, 시즌 기록, 보상, 한정 꾸미기 |

### 13.1 커플 PvP 디자인 원칙

- 현재 연결된 커플끼리만 대결한다.
- 공개 매칭·다른 커플·공개 순위표는 없다.
- 한 사람이 요청하고 상대가 수락해야 시작한다.
- 양쪽이 선택하기 전까지 상대의 `공격·방어·스킬`을 숨긴다.
- 코인·XP·인정 성공 수·연승·케미에 영향을 주지 않는다.
- 보상은 능력치 없는 배틀 메달 꾸미기다.
- 거절·만료·연결 종료에는 불이익이 없다.

### 13.2 P2 아트 계획

- 정식 레이드 일반 보스 3종: 잠꾸러기 마왕, 미루기 슬라임, 산만이 도깨비
- 시즌 한정 보스: 시즌당 1종
- PvP 선택 아이콘: 공격, 방어, 스킬 3종
- 배틀 메달과 프로필 테두리·승리 포즈·칭호: 수량 별도 제안
- HEAD·BODY·BACKGROUND 꾸미기: 최초 상점 수량 별도 제안

## 15. 검수 기준

다음 조건을 충족하면 디자인 납품이 완료된 것으로 본다.

- MVP 화면군과 핵심 분기·오류 상태가 누락되지 않았다.
- 화면 간 상태와 버튼 동작이 프로토타입에서 연결된다.
- 홈에 승인 대기·진행 중·결과 대기 건수가 모두 표시된다.
- 시작 승인과 결과 최종 승인이 시각적으로 명확히 구분된다.
- 츄코인 잠금·반환·보너스가 사용자가 이해할 수 있게 표현된다.
- 성장 시점이 첫 부화·20회·40회·60회·80회로 명확히 보인다.
- 5개 희귀도를 색상 외 수단으로 구분한다.
- 확률·천장·잔액·가격을 뽑기 전에 확인할 수 있다.
- 간이 협동 보스와 P2 정식 레이드·PvP가 혼동되지 않는다.
- 실패·거절·만료 문구가 비난하거나 불이익을 암시하지 않는다.
- 접근성 명암비, 글자 확대, 터치 영역과 모션 감소 대안이 명세돼 있다.
- 개발자가 별도 추측 없이 컴포넌트 상태와 에셋을 사용할 수 있다.

## 16. 디자이너 제안이 필요한 미확정 항목

아래 항목은 현재 기획에서 시각 규격이 확정되지 않았으므로 1차 무드보드 단계에서 2~3개 안을 제안받는다.

- 로고와 앱 아이콘 방향
- 전체 아트 스타일: 평면 벡터, 셀 셰이딩, 소프트 3D 등
- 실제 브랜드 컬러와 네 종류 배츄의 접근성 팔레트
- 한글·영문 폰트와 숫자 강조 방식
- 아이콘의 선형·채움형 사용 원칙
- 카드 모서리, 테두리, 그림자와 화면 밀도
- 배츄의 기본 체형과 성장 단계별 변화 폭
- 성공·실패 표정 레이어의 제작 범위
- 뽑기 연출의 강도와 모션 감소 대체 화면
- MVP 간이 협동 보스의 외형 콘셉트
- 하단 탭의 `배츄/몬스터`, `상점/뽑기` 최종 명칭에 대응하는 레이아웃
- P2 배틀 메달·꾸미기 최초 제작 수량과 예상 공수

## 17. 의뢰 시 함께 확정할 항목

- 작업 범위: MVP만 / MVP와 P2 콘셉트 / 전체 P2
- 캐릭터 일러스트와 UI 디자인을 한 디자이너가 모두 담당하는지 여부
- 모션 시안 또는 실제 Lottie·Rive 제작 포함 여부
- 기본 작업 해상도와 대응할 최소 화면 너비
- 1차 무드보드, 중간 검수, 최종 검수 일정
- 수정 가능 횟수
- 원본 파일과 저작권 귀속 범위
- 사용 폰트·아이콘·외부 에셋 라이선스
- 개발 전달 후 QA 대응 범위

---

최초 계약은 `브랜드 기초 + MVP 디자인 시스템 + MVP 핵심 프로토타입 + MVP 캐릭터·아이템 아트`를 우선하고, P2는 MVP의 시각 언어가 확정된 뒤 별도 계약으로 진행하는 것을 권장한다.
